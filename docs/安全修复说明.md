# 安全修复说明

日期：2026-10-12。基于上游提交 `577079e9a347555fadddd3865fc0bbcdb00d9fb4`。维护备注：maorongkang@gmail.com。

## 修复内容

| 原问题 | 修复后的行为 |
| --- | --- |
| 普通用户管理员可以直接给自己绑定超级管理员角色 | 用户写入统一经过 `UserAccessPolicy`；普通管理员只能向同部门用户授予本人已有角色，不能授予超级管理员角色 |
| 数据权限只限制查询，不限制编辑、停用、重置密码及删除 | 在事务内锁定目标用户并检查数据范围；禁止操作超级管理员和权限、数据范围高于自己的用户 |
| 可通过修改角色、菜单、部门结构间接扩大授权 | 缺少独立委派授权模型时，以上结构的写操作仅允许超级管理员；前后端返回的有效权限保持一致，查询权限保留 |
| 验证码答案在 JSON 和页面文本中直接暴露 | 返回 PNG 图片和随机标识，使用 `SecureRandom` 生成；Redis 原子消费，一次验证码只能校验一次 |
| 登录缺少频率限制和密码失败限制 | 验证码每 IP 每分钟30次、登录每 IP 每分钟60次；账号15分钟内累计5次密码错误后暂时拒绝登录，账号键统一大小写 |
| 改密和后台账号变更后旧令牌继续有效 | 用户增加 `session_version`，与资料、角色、状态或密码变更在同一数据库事务中递增；每个认证请求检查账号状态与会话版本 |
| 多角色、多岗位编辑时丢失原关联 | 列表返回 `deptId`、`roleIds`、`postIds`，两次批量查询补全关联；表单使用多选控件，不再按显示名称反查编号 |
| 部门可挂到自身或下级，移动后路径过期 | 部门结构变更串行锁定，拒绝环路，事务内按父子关系同步当前节点及全部后代路径 |
| 缺少请求校验和使用固定兜底密码 | 区分创建必填与可选更新，校验长度、状态、格式、关联编号及引用对象；创建和重置必须明确提交密码 |
| CSV 文本可被表格软件解释为公式 | 前后端导出工具为公式前缀添加文本标记，并保留原有 CSV 转义 |

内置管理员不能删除、停用或移除其超级管理员角色。已有停用角色、岗位的编号会完整回显；未改变的关联可以保留，新授予的关联必须有效。

密码保持原有6到64位长度范围，新设置的密码使用可见 ASCII 字符，以避免 BCrypt 的72字节上限与字符长度不一致。自助改密后前端立即清理本地会话并跳回登录页；后台编辑用户也会使该用户的旧会话失效。例外：操作人在用户管理中编辑自己的账号时不递增会话版本，当前会话保留，前端随即刷新用户、权限与菜单；权限与数据范围本就按请求实时计算，停用自己仍会因账号状态校验立即失效（2026-10-12 补充）。

限流默认使用实际 TCP 对端地址，忽略请求自行提供的 `X-Forwarded-For`。以后接入反向代理时，应另行配置受信代理的地址解析，避免所有用户共享代理地址的限额。

## 数据库初始化与旧库升级

没有修改已有的 V1、V2 迁移文件；新增 `scaffold-system/sql/V3__user_session_version.sql`。

- **全新空库**：按 V1 → V2 → V3 顺序导入。`DbInit` 是首次初始化工具，也会按版本顺序导入三份脚本。
- **已有 V1/V2 的库**：备份并确认库名后，仅执行 V3 一次。不要重新导入种子数据，也不要使用 `DbInit fix` 升级。
- **已执行过 V3**：不重复执行；该迁移新增列，重复执行会报字段已存在。
- 先完成数据库升级，再启动新版本后端。升级前发行的旧令牌会被拒绝，用户需重新登录。

可在 `scaffold-system` 目录使用 MySQL 客户端执行，以下占位符须替换为自己的连接信息，`-p` 会交互读取密码：

```text
mysql --host=<地址> --port=<端口> --user=<账号> -p --default-character-set=utf8mb4 <库名>
```

进入客户端后：

```sql
SOURCE sql/V3__user_session_version.sql;
SHOW COLUMNS FROM sys_user LIKE 'session_version';
```
